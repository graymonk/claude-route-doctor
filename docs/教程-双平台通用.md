# 如何长期稳定使用 Claude —— 双平台完整教程（实战验证版 v3.0）

> **这份教程是什么**：从零开始（选线路 → 搭/接节点 → 调客户端 → 环境检测排障 → 注册养号 → 用上 Claude Code），每一步都写清楚"点哪里、输什么、看到什么算成功"。Mac / Windows 双平台通用，差异处单独标注。
> **原理一句话**：Claude 会看"你从哪个 IP 来 + 你的电脑环境像不像当地人"。IP 干净、固定、住宅属性最佳；时区、语言、DNS、WebRTC 全部对齐，就不容易被风控。
> **本教程的底气**：全部排障结论来自 2026-10-28 的真机多轮调试——检测页从"DNS 泄露 + 出口漂移"修到全绿的全过程记录在附录C，每一条"为什么"都有实测依据。

| | 方案 A：机场订阅 + 住宅/AI 专线 | 方案 B：自建 VPS |

| 适合 | 已有机场、怕折腾 | 预算优先、想完全自主 |
| 成本 | 机场年费（几十~几百元） | VPS 年付 $12~25（约 ¥90~180） |
| 出口 IP 质量 | 住宅 IP 信任分普遍 90+（最优解） | 机房 IP 信任分 50~75，可用但非最优 |
| 时区 | 住宅节点在新加坡 = 免改时区；美国 = 要改一次 | 美国要改时区；新加坡免改 |

**先回答常见疑问：用新加坡 IP 是不是就不用改时区了？**

✅ 是的。中国和新加坡**同为 UTC+8**，系统时区天然一致，完全不用改；新加坡也是 Claude 官方支持地区，英语是官方语言之一，语言项风险也低。买任何机器/节点时**避开香港、澳门机房**（Claude 不支持，白买）。

> 方案 A 的用户请注意：本教程第七、八部分的大多数"坑"（出口漂移、加密 DNS 绕过分流、ECH）都发生在多节点订阅环境里，是实战踩出来的，务必读完。

## 第三部分：SSH 连上服务器

**Mac**：打开「终端」App（`Command + 空格` 聚焦搜索 → 输入「终端」→ 回车）：

```bash
ssh root@你的VPS的IP
```

第一次连接问 `Are you sure you want to continue connecting?` → 输 `yes` 回车；提示 `password:` 时输入 root 密码（**屏幕不显示任何字符是正常的**，可先复制再 `Command + V` 粘贴）。

**Windows**：按 `Win + R` → 输入 `powershell` → 回车，同样执行 `ssh root@你的VPS的IP`；粘贴 = **鼠标右键**。

看到 `root@xxxx:~#` 提示符就是连上了，之后所有服务器命令都在这个窗口输。

## 第四部分：（方案 B）搭节点 + Xray 降级

### 4.1 一条命令装好 Reality 节点

```bash
bash <(wget -qO- -o /dev/null https://github.com/233boy/Xray/raw/main/install.sh)
```

1. 装完输入 `xray` 回车进管理菜单
2. 添加节点，协议选 **VLESS-Reality**（默认推荐项），端口定一个好记的（如 `5835`）
3. 输入 `xray url` 回车 → 输出一条 **`vless://` 开头的长链接**，这就是节点的"身份证"，复制保存。里面的 uuid、公钥 pbk、short-id sid、SNI **全部以这条链接为准**

### 4.2 【必做】把 Xray 降级到 v25.12.8

> ⚠️ **为什么**：Xray v26 系列改了 Reality 认证算法，Clash Verge 的内核（mihomo）连不上，报 `REALITY authentication failed`。不降级 = 白搭。

逐条粘贴执行（每条等它跑完再下一条）：

```bash
apt install -y unzip wget
wget -q https://github.com/XTLS/Xray-core/releases/download/v25.12.8/Xray-linux-64.zip -O /tmp/xray.zip
rm -rf /tmp/xraynew && mkdir -p /tmp/xraynew && unzip -o /tmp/xray.zip xray -d /tmp/xraynew
systemctl stop xray
cp /tmp/xraynew/xray /usr/local/bin/xray
systemctl start xray
```

验证（应显示 `Xray 25.12.8` 且状态 active）：

```bash
/usr/local/bin/xray version
systemctl is-active xray
```

> 以后哪天突然连不上，先回服务器跑 `/usr/local/bin/xray version` 看是不是被升级到 v26 了。

## 第六部分：把节点导入 Clash Verge

### 方案 A：机场订阅

1. 复制机场的**订阅链接**
2. Clash Verge 左侧「订阅」→ 顶部输入框粘贴 → 导入
3. 选中该订阅（右键 → 使用），左侧「代理」页选中节点/分组
4. ⚠️ **关键**：进入「代理」页确认 claude.ai 会走哪个组/节点——
   - 有「AI」类专用组的，手动**选定住宅/AI 专线节点**（别留自动选择）；
   - **绝对不要用"负载均衡"类型的组**承载 Claude（每次连接换出口 IP，风控重灾区）；

### 方案 B：自建节点

方法一（推荐）：复制 `vless://` 链接 → 「订阅」→ 粘贴导入（会自动转成本地配置）。

方法二：用本仓库 [docs/自建节点基础配置.yaml](自建节点基础配置.yaml)，替换 `<你的VPS的IP>` 等占位内容后，「订阅」→ 新建 → 选择本地文件导入。

**验证**：选中节点后浏览器打开 https://www.google.com 能出来，节点就通了。

## 第七部分：⭐ 客户端设置（本教程核心经验，决定成败）

> 这一整部分是 2026-10-28 实战的最终结论。当时检测页分数从 97 掉到 79 再拉回来，全部根因都在这一部分。完整过程见附录C。

### 7.1 三种代理模式，到底差在哪（一张表看懂）

| | 只开系统代理 | 只开 TUN | **双开（最终推荐）** |
|---|---|---|---|
| 浏览器怎么连 | 把域名**明文**交给 Clash（最可靠） | 本地自己做 TLS 握手 | 走系统代理（域名明文） |
| 域名分流可靠性 | ✅ 最高，加密干扰无效 | ⚠️ 依赖嗅探；遇到 ECH 加密会失灵 | ✅ 最高 |
| UDP / WebRTC | ❌ 绕过代理，**漏真实 IP** | ✅ 全部接管 | ✅ TUN 兜底接管 |
| 浏览器加密 DNS 的影响 | 不影响分流 | DoH 拿到真实 IP，**绕过域名分流** | 不影响（域名走明文通道） |
| 结论 | 配合附录A 才完整 | 有 ECH 风险，不推荐单独用 | **最终形态** |

**为什么只开 TUN 会翻车（97 → 79 之谜）**：开了浏览器"安全 DNS"后，Chrome 自己解析出 claude.ai 的真实 IP，Clash 看到的只是一个纯 IP 连接；靠嗅探（sniffer）能恢复域名，但 claude.ai 套在 Cloudflare 后面，Chrome 还会用 **ECH 把握手里的域名加密**，嗅探也瞎了——于是 claude.ai 的流量掉进普通机房节点，信任分从 97（住宅）掉到 79（机房）。而 Chrome 新版已经**移除了关闭 ECH 的开关**，此路不通。开系统代理后，Chrome 根本不在本地做握手，域名明文交给 Clash，加密干扰全部失效。

### 7.2 最终形态：三个开关全部常开

| 开关 | 位置 | 状态 |
|---|---|---|
| TUN 模式 | 设置页 | ✅ 开（接管全部流量含 UDP） |
| 系统代理 | 设置页 | ✅ 开（浏览器域名明文进 Clash，分流最稳） |
| Chrome 安全 DNS | Chrome → 设置 → 隐私和安全 → 安全 → 使用安全 DNS → **Cloudflare (1.1.1.1)** | ✅ 开（双开时它主要起兜底作用，无害） |

三者互不冲突，是实战验证的组合，**不要因为"想省事"关掉任何一个**。

### 7.3 TUN 设置要点

设置 → 点「TUN 模式」旁的设置（虚拟网卡模式）：

- **TUN 模式堆栈：选 Mixed**（默认 gVisor 是纯用户态协议栈，明显更慢——这是"TUN 感觉变慢"的最大原因）
- 严格路由：建议开（防泄漏更稳；若导致内网设备/打印机访问异常，可关掉并用附录A 兜底）
- IPv6：关
- DNS 劫持：`any:53`（默认）
- MTU：1500（默认）

改完点**保存**。

### 7.4 速度经验

- claude.ai 延迟 250~650ms 属正常——住宅/专线是两跳链（中继 → 住宅出口），这是拿高信任分换的，别指望追平直连节点
- 想提速：到「代理」页把承载 Claude 的**中转组**挨个换节点，每换一次看检测页 claude.ai 延迟，挑最快的固定；香港/日本中继 → 美国住宅的"V 字形"路由有时更快
- 机场方案下只有 claude.ai 慢一点，其他网站照常走普通快节点
- 提速红线：**不要**为此把 Claude 切到普通机房节点

## 第八部分：⭐ 环境检测与排障手册

### 8.1 先做检测，学会看结果

挂着节点，浏览器打开 **https://ip.net.coffee/claude/**，逐卡对照（v3.0 修订版标准，比旧版更贴近实战）：

| 检测卡片 | 合格标准 | 说明 |
|---|---|---|
| **Claude AI 出口IP** | = 你的住宅/专线节点 IP | **唯一的"成绩单"**，这才是 Claude 眼中的你 |
| **Claude AI 信任分** | 住宅 IP 90+ 最佳；机房 IP 50~75 可用 | 「家庭住宅IP (ISP)」>「机房IP (Hosting)」；「不可访问」= 必须换 IP |
| VPN / 代理 / Tor / 机器人 | 全部"未检测到" | 出现 = IP 被标记，换节点/IP |
| DNS 泄露 | 「未检测到泄漏」 | **唯一红线是"中国DNS"**；显示 Google/Cloudflare、地理位置香港或美国都算过（见 8.9） |
| WebRTC UDP 泄露 | UDP 出口 = 海外节点即可 | 「异常」标签 ≠ 泄露！见 8.5 |
| 时区 / 语言 | 一致 | 不一致看 8.2 / 8.3 |
| 中国出口IPV4 | **显示什么都行** | 这张卡是检测站特意探测你直连线路的展示位（走直连规则），Claude 永远看不到 |
| Cloudflare 出口IP | **显示什么都行** | 另一条链路/任播节点，与 Claude 出口不同属正常 |

> 旧版教程要求"三个出口 IP 相同"，那只适用于自建单节点全局代理。**机场分流方案请以「Claude AI 出口IP」和信任分为准。**

### 8.2 时区不一致 → 改系统时区（美国 IP 必做；新加坡 IP 免做）

以纽约 IP 为例：

**Mac**：苹果菜单  → 系统设置 → 通用 → 日期与时间 → 关闭「使用当前位置自动设定时区」→ 地图上点纽约（或输入 `New York` 回车）。想同时看北京时间：系统设置 → 控制中心 → 菜单栏时钟选项加显城市。

**Windows**：开始 → 设置 → 时间和语言 → 日期和时间 → 关闭「自动设置时区」→ 时区选 **(UTC-05:00) 东部时间**（洛杉矶选太平洋时间）。

改完刷新检测页，「时区一致」变绿。

### 8.3 语言不一致 → 浏览器语言把英文排第一

1. 地址栏输入 `chrome://settings/languages`（Edge 是 `edge://settings/languages`）
2. 添加语言 → 搜 **English (United States)**
3. 把 English **移到第一位**（右侧"…" → 置顶）
4. 重启浏览器重测
5. Mac 用户建议直接用 Chrome/Edge（Safari 跟随系统语言，动静太大）；不想改全局的，给 Claude 单开一个浏览器「用户配置文件」单独设置

### 8.4 出现"当前为 IPv6 环境"黄条 → 关 IPv6

1. Clash Verge：设置 → Clash 设置 → IPv6 关；TUN 设置里 IPv6 也保持关
2. Mac 系统级：系统设置 → 网络 → Wi-Fi → 详细信息 → TCP/IP → 配置 IPv6 选「仅本地链接」；或终端执行 `networksetup -setv6off Wi-Fi`（插网线换对应服务名，`networksetup -listallnetworkservices` 可查）
3. Windows 系统级：控制面板 → 网络和 Internet → 网络连接 → 右键 WLAN → 属性 → 取消勾选 **Internet 协议版本 6 (TCP/IPv6)**
4. 重启浏览器重测

### 8.5 WebRTC UDP 泄露 → 先分清"真泄露"还是"假警告"

**看 UDP 出口显示的是谁**：

- 显示**你的国内真实 IP**（如电信 113.x / 219.x）→ 真泄露。修法：TUN 开着一般自动好；仍漏就装 uBlock Origin 扩展 → 勾选"防止 WebRTC 泄漏本地 IP"。复查 https://browserleaks.com/webrtc 不能出现真实 IP
- 显示**海外节点 IP** + 一个「异常」标签 → **不是泄露，不用管**。「异常」只表示"UDP 出口和 Claude 出口不是同一个节点"（比如 UDP 走圣何塞、Claude 走纽约）。claude.ai 网页本身不用 WebRTC，Claude 看不到这个差异

### 8.6 DNS 泄露（显示"中国DNS"）→ 三级排查

> 判定红线只有一个：DNS 出口显示**国内运营商**（电信/联通/移动，如 113.x、219.x、183.x）。显示 Google、Cloudflare 等海外服务商即合格。

**第一级（多数情况够用）**：TUN 设置里「严格路由」开 + 设置里「DNS 覆写」开 → 重启 Clash Verge 和浏览器再测。

**第二级**：确认 Chrome 安全 DNS 已设为 Cloudflare (1.1.1.1)（见 7.2）。

**第三级（实战根治法，双开模式必用）**：如果开了系统代理后 DNS 又显示中国 DNS——原因是 Clash 给"不在分流名单里的域名"做解析时，默认用的是国内上游（223.5.5.5 / 119.29.29.29），把运营商信息带了出去。修法：套用 **附录A 增强配置**，把默认解析改为经代理发送的 Cloudflare/Google 加密 DNS。国内域名的解析策略不受影响。改完必须**重新激活订阅**再测。

### 8.7 信任分低 / 被标记滥用

- 住宅 IP（90+）是核心资产；机房 IP 50~75「良好」也能用
- 「不可访问」或滥用记录一大片：方案 B 去 RackNerd 提工单付费换 IP（几美元），新加坡 Vultr 直接 Destroy 重建（损失几毛钱）；方案 A 换一个住宅节点重新测
- 换 IP 后：重做 8.1 起的整套检测

### 8.8 ⭐ 出口 IP 变机房 / 信任分骤降（如 97 → 79）→ 五步排查

> 症状：之前 90+ 住宅，某次改设置后变 70~80 机房，或 Claude 出口 IP 换成了陌生机房地址。
> 本质：**claude.ai 的流量没走锁定/住宅节点，掉进了普通节点。** 按顺序查：

1. **查三个开关**：TUN、系统代理、Chrome 安全 DNS 是否都在开（7.2）。最常见的翻车：只开 TUN + Chrome 安全 DNS → 加密 DNS 绕过域名分流
2. **查分组**：「代理」页看 claude.ai 用的是哪个组、组里选的哪个节点——是否被切到机房节点；是否在"负载均衡"组（必须退出）
3. **查嗅探配置**：附录A 的 sniffer 是否已粘贴并重新激活（只开 TUN 的场景必需）
4. **ECH 教训**：只开 TUN 时，Chrome 的加密 ClientHello 会把域名藏起来让嗅探失效，且新版 Chrome 已移除关闭开关 → **开系统代理即解**（7.1）
5. **重新激活**：每次改动配置后，订阅页右键 →「使用」重新激活，再去检测页重测。一次只改一个变量，否则不知道是哪步起了作用

### 8.9 DNS 出口显示香港/美国 → 正常，别再折腾

8.8.8.8 / 1.1.1.1 是全球任播服务，代理链路在哪中转，Google/Cloudflare 就从最近的节点应答——链路过香港就显示香港。**判定 DNS 合格只看一条：服务商是不是海外（非中国运营商）**。claude.ai 本身的解析发生在出口端（系统代理模式下域名原样进隧道、由出口服务器解析），和这张卡显示的地理位置无关。想让卡片显示美国图标可以改（把附录A 里 DoH 的 `#组名` 改成 Claude 住宅组），但不值得——平白让住宅链分担全局 DNS。

### 8.10 排障方法论（少走弯路的四条军规）

1. **一次只改一个变量**，改完立刻重测，否则无法归因
2. **改配置 ≠ 生效**：动过 yaml/增强配置后，必须订阅页右键 →「使用」重新激活（或设置 → 重启内核）
3. **怀疑配置没生效**：Clash Verge 数据目录下的运行时配置 `clash-verge.yaml` 里搜关键字（如 `sniffer`）确认是否已合入
4. **改前必备份**：手动改文件前先复制一份 `.bak-日期`

### 8.11 一张表总结：异常怎么办

| 检测页现象 | 性质 | 修法 |
|---|---|---|
| DNS 显示中国DNS/运营商 | 真泄露 | 8.6 三级排查（根治：附录A） |
| UDP 出口 = 国内真实 IP | 真泄露 | 8.5：开 TUN / uBlock 拦截 |
| UDP 出口 = 海外但有「异常」标签 | 假警告 | 不用管（出口不一致而已） |
| Claude 出口 ≠ 你的住宅节点 / 分数骤降 | 分流失灵 | 8.8 五步排查 |
| 时区不一致 | 高风险 | 8.2（新加坡 IP 免做） |
| 语言不一致 | 中风险 | 8.3 |
| IPv6 黄条 | 暴露真实网络 | 8.4 |
| 信任分低 / 滥用记录 | 直接风控 | 8.7 换 IP/节点 |
| TUN 感觉变慢 | gVisor 栈 | 7.3 Stack 改 Mixed |
| 三个出口 IP 不相同（自建方案） | 代理没生效 | 检查节点选中、开关状态 |

## 第九部分：白嫖无限邮箱（可选但推荐）

原理：域名托管到 Cloudflare，开启"捕获所有（Catch-all）"，`任意名字@你的域名` 都转发到真实邮箱，别名无限多，一人一号。

1. **买域名**：Namesilo（https://www.namesilo.com ，支持支付宝）或 Spaceship（https://www.spaceship.com ），几块钱/年，选 .com/.net/.me 等正规后缀
2. **添加到 Cloudflare**：https://dash.cloudflare.com 注册（免费）→ 添加站点 → 输域名 → Free 套餐 → 记下两个 NS 地址
3. **改 NS**：回注册商域名管理 → Nameservers → 自定义 → 填入 Cloudflare 的两个 NS → 保存（几分钟到几小时生效）
4. **开邮件路由**：Cloudflare 选中域名 → 电子邮件 → 电子邮件路由 → 开始使用 → 目标地址填真实邮箱并收验证邮件 → 路由规则启用 **捕获所有** → 发送到真实邮箱
5. **测试**：用别的邮箱给 `test123@你的域名` 发信，真实邮箱收到即成功
6. 注册 Claude 时填别名（claude01@、claude02@…），验证码都进真实邮箱

> 邮件路由只能收不能发；要发信用 Zoho Mail 免费版（https://www.zoho.com/mail/ ）配 SMTP。注册 Claude 只需要收。

## 附录A：Clash Verge 增强配置（防泄露核心，机场/自建都建议）

> **解决两个问题**：① 浏览器加密 DNS（DoH）绕过域名分流、ECH 加密致嗅探失效 → 出口漂移；② Clash 默认国内上游 DNS 泄露运营商信息 → "中国DNS"。
> **存放在哪**：「订阅」页 → 右键你的订阅 →「**扩展覆写配置**」→ 整段粘贴 → 保存 → 右键「**使用**」重新激活。它是独立文件，**订阅自动更新不会覆盖**；改前建议先备份原内容。

```yaml
sniffer:
  enable: true
  parse-pure-ip: true
  override-destination: false
  sniff:
    TLS:
      ports: [443, 8443]
    QUIC:
      ports: [443]
    HTTP:
      ports: [80, 8080]
  force-domain:
    - +.claude.ai
    - +.anthropic.com
    - +.claudeusercontent.com

dns:
  nameserver:
    - "https://1.1.1.1/dns-query#你的主力节点组名"
    - "https://8.8.8.8/dns-query#你的主力节点组名"
```

**使用注意**：

- `#你的主力节点组名`：表示 DNS 查询经该代理组发出。把组名换成你「代理」页里**真实存在的组名**（机场一般是"🔰国外流量/节点选择"之类；自建单节点配置写 `Proxy`）。组名带 emoji 也没关系，照抄即可
- 国内域名的解析仍按订阅原有策略走国内 DNS，速度不受影响
- 验证是否生效：检测页 DNS 卡应显示 Google/Cloudflare（海外）且"未检测到泄露"；`clash-verge.yaml` 运行时配置里能搜到 `sniffer`
- 进阶（可选）：想给 Claude 域名单独锁住宅节点，在机场订阅的分组里手动选定；或在扩展覆写里追加规则（放在订阅规则之前）：
  ```yaml
  rules:
    - DOMAIN-SUFFIX,claude.ai,你的住宅节点或组
    - DOMAIN-SUFFIX,anthropic.com,你的住宅节点或组
    - DOMAIN-SUFFIX,claudeusercontent.com,你的住宅节点或组
  ```

## 附录C：2026-10-28 实战排障记录（本教程的由来）

环境：Mac（Apple Silicon）+ Clash Verge Rev + 机场订阅「AI专用」（含住宅专线）+ 检测页 ip.net.coffee/claude。

| 轮次 | 操作状态 | 检测结果 | 结论 |
|---|---|---|---|
| 1 | 只开系统代理 + Chrome 安全 DNS | 出口=住宅 97 ✓；DNS=中国电信 ✗ | 出口对，但 Clash 上游 DNS 泄露运营商信息 |
| 2 | 只开 TUN（无嗅探） | DNS=Cloudflare ✓；出口=机房 79 ✗ | TUN 下加密 DNS 绕过域名分流，出口漂移 |
| 3 | TUN + 嗅探配置（附录A sniffer） | 出口仍机房 ✗ | claude.ai 的 ECH 把握手域名加密，嗅探致盲 |
| 4 | 尝试关 Chrome ECH | flags 开关已被 Chrome 移除 | 此路不通，必须让域名走明文通道 |
| 5 | **双开（TUN+系统代理）+ 嗅探** | 出口=住宅 97 ✓；DNS=中国电信 ✗ | 出口稳了；DNS 泄露随系统代理回归 |
| 6 | 追加 **DNS 上游改造**（附录A dns 段） | **出口=住宅 97 ✓；DNS=Google ✓ 全绿** | 最终形态达成 |

**提炼出的三条铁律**：
1. 系统代理负责"域名分流可靠"，TUN 负责"UDP 不漏"，加密 DNS 上游负责"解析不泄露"——三者各管一件事，缺一不可；
2. 排障时一次只改一个变量，改完重新激活再测；
3. 检测页里"中国DNS"和"UDP 出口=真实 IP"是仅有的两个真泄露；其余黄标（出口不一致的"异常"、中国出口卡、海外 DNS 的地理归属）都是噪声。
